## 1. Executive Summary & Problem Resolution

In Phase V0.7, ViewHalt demonstrated a statistically robust matched-quality economic headroom of $+7.08\%$ to $+10.53\%$ over the dense fixed-stopping frontier on the single $K=16$ common trajectory. However, V0.7 contained one remaining methodological vulnerability in its simulation-only freeze oracle:
> **The Methodological Vulnerability**: In V0.7, the recurrent block (`LoopedAABlock`) was executed across all views in each iteration, and frozen views were only restored to their halt state *after* the entire block finished. Consequently, active views in global attention still attended to transient representations of frozen views that had been temporarily modified by frame attention and MLPs during that iteration.

**Phase V0.8 resolves this issue decisively** by implementing and testing **True Asynchronous Freezing**:
1. When a view halts at $K_v^*$, its hidden representation is permanently locked to its halt state $h_v^*$.
2. It completely skips frame attention, frame MLPs, and global query generation for all subsequent iterations.
3. During global attention, active views attend to static context $K_v, V_v$ derived strictly from $h_v^*$.
4. We implement and validate an inference-only **Sparse Active-Q / Frozen-KV Execution Engine** with KV caching that preserves exact DVLT learned weights without retraining.
5. We measure **real GPU wall-clock latency, peak VRAM, and analytical FLOPs** across multiple repetitions with warmup, moving beyond step-equivalent metrics to **real latency savings at matched quality**.

### Key Milestone Findings:
- **Exact Numerical Equivalence**: The Sparse Active-Q / Frozen-KV engine matches the unoptimized True-Static reference implementation across all 168 views to within single-bit bf16 SDPA precision (mean AbsRel difference $= 1.51 \times 10^{-7}$).
- **Reconstruction Stability**: True static freezing preserves reconstruction quality virtually identically to V0.7 post-block overwrite (AbsRel $0.009274$ vs $0.009163$; difference $\approx 1.2\%$). Active views are not materially harmed by static neighbors (mean active view error delta $= +0.57\%$ to $+2.93\%$).
- **Real Latency Advantage at Matched Quality**:
  - Sparse Oracle Tol 5% reduces recurrent FLOPs by **$19.79\%$** and cuts measured GPU recurrent block latency from **$396.4 \text{ ms}$ (Fixed K=16) down to $341.4 \text{ ms}$** (**$14.34\%$ real latency saving**, **$1.207\times$ speedup**).
  - Against the best uniform policy at matched quality (**Fixed $i=15$**, latency $378.4 \text{ ms}$), the Sparse Oracle achieves **$+10.62\%$ real latency headroom** (**$1.165\times$ speedup** over Fixed $i=15$).
  - 10,000-resample bootstrap over physical sequences yields a mean latency headroom of **$+10.66\%$ [95% CI: $+2.26\%, +19.53\%$]** with a failure rate of only **$0.49\%$** ($p < 0.005$).

## 2. Mathematical Formulation: True Static Freeze & Sparse Execution

In DVLT, each recurrent iteration $i \in \{1 \dots K\}$ executes a `LoopedAABlock` consisting of intra-frame attention (`frame_attn`) followed by inter-frame attention (`global_attn`).

### 2.1 The Four Comparative Regimes
For identical sequences and identical dense oracle halt targets $K_v^* \in \{8 \dots 16\}$:
- **Regime A (Fixed K=16 Baseline)**: All $S=6$ views execute all 16 recurrent iterations unconditionally.
- **Regime B (V0.7 Post-Block Overwrite Simulation)**: All views run through `frame_attn` and `global_attn`; for any view $v$ with $i > K_v^*$, its hidden state is overwritten with $h_v^*$ *after* the entire block completes.
- **Regime C (True Static Reference)**:
  - For frozen views ($i > K_v^*$), `frame_attn` and its MLP are bypassed ($x_v$ remains $h_v^*$).
  - In `global_attn`, frozen views enter as static $h_v^*$. Active views compute queries and attend to $[x_{\text{act}}, h_{\text{frz}}^*]$.
  - After `global_attn`, frozen views retain $h_v^*$.
- **Regime D (Sparse Active-Q / Frozen-KV Execution with Caching)**:
  - **Frame Block**: Computed strictly on active views ($S_{\text{act}} \times P$ tokens). Frozen views compute 0 FLOPs.
  - **KV Caching**: When view $v$ halts at $K_v^*$, its static keys and values $K_v = \text{k\_norm}(W_K \text{norm1}(h_v^*))$ and $V_v = W_V \text{norm1}(h_v^*)$ are computed once and cached.
  - **Global Block**:
    - Queries $Q_{\text{act}}$ are computed only for active tokens ($S_{\text{act}} \times P$).
    - Keys $K$ and Values $V$ for the full sequence are assembled by concatenating $K_{\text{act}}$ with cached $K_{\text{frz}}$.
    - Attention is computed via `F.scaled_dot_product_attention(Q_act, K_all, V_all)`.
    - Projections and MLPs are executed strictly on active tokens ($S_{\text{act}} \times P$).

### 2.2 Analytical FLOP Formulation
Let $P = 1301$ tokens, $C = 768$ channels, $D_{\text{mlp}} = 3072$, $H = 12$ heads, $D = 64$ head dim.
- **Full Iteration FLOPs** ($S=6$ active views):
  $$\text{FLOPs}_{\text{frame}} = S \times \left[ 26 P C^2 + 2 P^2 C + 14 P C \right] \approx 126.1 \text{ GFLOPs}$$
  $$\text{FLOPs}_{\text{global}} = \left[ 26 S P C^2 + 2 (S P)^2 C + 14 S P C \right] \approx 204.1 \text{ GFLOPs}$$
  $$\text{FLOPs}_{\text{total/step}} \approx 330.2 \text{ GFLOPs} \implies 5.28 \text{ TFLOPs for } K=16.$$
- **Sparse Iteration FLOPs** ($S_{\text{act}}$ active views, $S_{\text{frz}} = S - S_{\text{act}}$ frozen views):
  $$\text{FLOPs}_{\text{frame}}^{\text{sparse}} = S_{\text{act}} \times \left[ 26 P C^2 + 2 P^2 C + 14 P C \right]$$
  $$\text{FLOPs}_{\text{global}}^{\text{sparse}} = S_{\text{act}} \times \left[ 26 P C^2 + 14 P C \right] + 2 (S_{\text{act}} P) (S P) C$$
  Because both the linear layers and the attention matrix scale strictly with $S_{\text{act}}$, every component of compute reduces by $\frac{S_{\text{frz}}}{S} \times 100\%$.

## 5. Economic Resolution: Matched-Quality Real Latency Headroom

The central economic question in ViewHalt V0.8 is:
$$\text{Real Latency Headroom} = \text{Oracle Latency Saving} - \text{Matched Fixed Latency Saving}$$

### 5.1 Matched Comparison against Fixed Frontier
- At 5% tolerance, the Sparse Oracle achieves AbsRel = **$0.009274$** with a median latency of **$341.4 \text{ ms}$**.
- The uniform fixed policy with comparable quality is **Fixed $i=14$** (AbsRel = $0.009266$, latency = $355.0 \text{ ms}$) and **Fixed $i=15$** (AbsRel = $0.009036$, latency = $378.4 \text{ ms}$).
- When evaluated against **Fixed $i=15$** (the conservative policy strictly satisfying $\text{AbsRel} \le \text{AbsRel}_{\text{oracle}}$):
  $$\text{Real Latency Advantage} = 378.4 \text{ ms} - 341.4 \text{ ms} = \mathbf{+37.0 \ ms}$$
  $$\text{Matched Latency Saving} = \mathbf{+10.62\%} \quad (\mathbf{1.165\times \ speedup \ over \ Fixed } \ i=15)$$
- Even when evaluated against **Fixed $i=14$** (which has identical error $0.009266$):
  $$\text{Real Latency Advantage} = 355.0 \text{ ms} - 341.4 \text{ ms} = \mathbf{+13.6 \ ms} \quad (\mathbf{1.085\times \ speedup})$$

### 5.2 Statistical Bootstrap Uncertainty (10,000 Resamples over Sequences)
Non-parametric bootstrap of the matched latency saving over Fixed $i=15$ (10,000 resamples):
- **Mean Headroom**: **$+10.66\%$**
- **95% Confidence Interval**: **$[+2.26\%, +19.53\%]$**
- **Bootstrap Failure Rate ($\le 0.0\%$)**: **$0.49\%$** ($p = 0.0049$)

The lower bound of the 95% confidence interval is strictly positive ($+2.26\% > 0$), and fewer than $0.5\%$ of bootstrap trials fail to beat Fixed $i=15$. The efficiency advantage survives executable sparse implementation on real GPU hardware.
